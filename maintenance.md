## Gotchas / Known Issues

**Frigate / cameras**
- **Reolink stream paths lie about codec.** Both E1 Zoom streams use the `h264Preview_` prefix, but the *main* stream actually encodes HEVC/H.265 4K — verified via ffprobe. There is no `h265Preview_` path on this camera. Never trust the path name for codec; always probe it. This was the #1 near-miss on the Frigate bring-up.
- **RTSP `401 Unauthorized` is often not a real auth failure.** A stray space after `admin:` or an unescaped special character in the password breaks URL parsing and surfaces as a 401. Percent-encode symbols in RTSP passwords before debugging further.
- **Explicit `detect.width`/`detect.height` required.** Frigate 0.17 changed camera-resolution auto-detection; some cameras make Frigate hang on startup if these aren't set explicitly.
- **Model path must match the actual export filename exactly**, or Frigate errors at start. Re-exporting a different model size/imgsz means updating both the export command and `model.path` in config.
- **The `.trt` engine is GPU/driver-specific.** After a driver bump or a future GPU swap, delete the cached TensorRT engine and let Frigate rebuild it on next start.
- **H.265 live view over WebRTC can be flaky in-browser.** Detection runs on the H.264 sub-stream so detection itself is unaffected — if only the *main* live view misbehaves, that's why, not a detection problem.
- **YAML pasted from a rich-text source can silently corrupt config.** Smart quotes and non-breaking spaces from copy-paste break YAML parsing without an obvious error. Create/edit config with a plain editor (nano) or a clean ASCII heredoc.
- **Both current camera streams carry AAC audio**, and recording captures audio by default — relevant if operating in a two-party-consent state (see `todo.md` → Frigate).

**SSH / terminal**
- **Pasting a long unbroken line (a 64+ character SHA256 digest, an interpolated RTSP URL with a long variable) into this SSH session can silently corrupt it mid-paste** — characters go missing or the line splits mid-token, with no error at paste time. Seen twice: once truncating a `${FRIGATE_RTSP_PASSWORD_...}` substitution and a camera IP, once truncating a Docker image's SHA256 digest. Mitigations: avoid digest-pinning images (tag pins are short and this repo does that everywhere else anyway); for anything that must be long, write it to a script file via a quoted heredoc (`<<'EOF'`) and execute the file, or verify what actually landed on disk with `cat`/`grep` afterward rather than trusting the echoed terminal output.

**Immich**
- **External Libraries don't auto-watch the filesystem.** A folder added as an External Library only gets re-indexed on a manual "Scan" or a configured rescan schedule (Administration → Settings → External Library) — updating the files on disk (e.g. via rclone) does nothing to Immich's index until a scan runs.
- **"Read-only awareness" was removed from External Libraries upstream.** Mounting a library path `:ro` still fully protects the files (the OS blocks the write), but Immich's UI will report an edit/delete as successful even when the underlying mount silently blocked it. Confusing if you don't know to expect it; harmless to the actual files.

**GPU / NVIDIA driver**
- **`nvidia-persistenced` is a systemd `static` unit** — no `[Install]` section, so it can't be `systemctl enable`d in the normal sense, and critically it does **not** auto-restart if it dies (died 2026-09-11, presumably on a signal during some other event, and simply stayed dead for over a month). While it's down, GPU containers that are already running (Plex) keep working, but any *new* GPU container creation (a fresh `docker compose up`, a restart) fails immediately with a `/run/nvidia-persistenced/socket` mount error — looks like a container problem, isn't one.
- **`nvidia-smi` reporting "Driver/library version mismatch"** means the loaded kernel module and the userspace library disagree on version — compare `cat /proc/driver/nvidia/version` against `nvidia-smi`'s header to confirm. Happens when a driver package updates without the kernel module reloading (which it can't do live while anything holds the GPU open). Check `lsmod | grep nvidia` for nonzero "Used by" counts before even considering `rmmod` — if something holds it open that `fuser /dev/nvidia*` can't identify, a clean reboot is the safer fix; forcing an unload risks a stuck module that needs a hard reset anyway.

**Storage / drives**
- **NVMe drive letters are not stable across reboots** — proven twice on this box (Docker's data drive moved from `nvme1n1` to `nvme0n1` on one reboot). Only `/dev/disk/by-id/` or `UUID=` fstab entries survive this; never reference `/dev/sdX`/`/dev/nvmeXnY` directly.
- **Two visually-identical WD Red 4TB drives exist in this box** — same model string `WDC_WD40EFZX-68AWUN0`, only the serial differs. `WX32D124UYHS` = `/mnt/backup`. `WX62D12CCFRX` = `/mnt/media` (holds the verified Plex library — never reformat without resolving by serial first).

**Eversolo DMP-A6 Gen 2**
- **It's an SMB server, not really a usable SMB client.** It shares its own storage out to the network well; browsing an external share (like server01's `media`) from its own UI for playback appears limited. Plan accordingly: pull files off it via a PC, don't expect it to mount/play from server01 directly over SMB.
- **SMB username is `root`, only shown on the unit's physical screen** (not the iOS app). Password is whatever's set in the same on-device menu. Explorer doesn't prompt for credentials on its own — authenticate first via `net use \\<ip>\IPC$ /user:root <password>` in PowerShell, then browse. Its one share is just named `Share`.

**Samba (`dperson/samba`)**
- **`docker compose up -d` alone does not clear removed shares/state** — it reuses the container's internal storage across recreations. Use `docker compose down` then `up -d` for any change that should fully reset the running config (removed shares, account changes), not just repeated `up -d`.
- **The `-s` share flag's real field order is `name;path;browsable;readonly;guest;users`** — not `browsable;guest;readonly`. Getting this wrong doesn't error, it silently sets the wrong permissions. Always confirm the live config with `docker exec <container> testparm -s` after any share change; don't trust `net view` or Explorer alone, since they can look consistent even when the underlying config is wrong.
- **Writes fail silently (permission denied) if the container's internal `smbuser` UID doesn't match the host owner of the bind-mounted path.** Reads still work (world-readable dirs), which makes this confusing. Set `USERID`/`GROUPID` env vars to match the host user (1000 for `ian`) and verify with `docker exec <container> id smbuser`.

**Verify workflow** (from the 2026-07-08 manifest-verify detour above — the process this prevents)
- Strip the same `./` path prefix identically on both manifests being compared, or every line will false-mismatch.
- Both inputs to `comm`/`sort` need `LC_ALL=C`, or locale-dependent sort order breaks the diff.
- `comm` compares whole lines — hash *and* path both have to match, so a manifest format drift between two runs looks like total data loss even when the data is fine.
- Re-hash from the live source, not a manifest that might be stale relative to it, whenever verification results look suspicious.

## Quick Reference

- **Canonical file-verify pattern** (any future bulk copy): hash both sides with the same tool and the same `./` strip, `LC_ALL=C sort` both manifests, `comm -23 src dst | wc -l` → 0 means clean. Always run in tmux with stderr captured to a file.
- **Frigate RTSP stream probe** (any camera): `docker run --rm --entrypoint ffprobe linuxserver/ffmpeg -v error -show_entries stream=codec_name,width,height -of default=noprint_wrappers=1 "rtsp://USER:PASS@IP:554/PATH"`.
- **OneDrive sync check:** `tmux attach -t onedrive` (Ctrl-b then d to detach without stopping); log at `~/rclone-onedrive-initial.log`; sanity check with `rclone lsd onedrive:`.
- **rclone re-auth** if the refresh token ever lapses (~90 days unused): `rclone config reconnect onedrive:` plus one browser round-trip.
- **Plex HW-transcode check:** play a video, force a lower quality, dashboard should show "(hw)".
